# Astra Project Forge — Attribution Policy

This file documents the project attribution policy for redistributed or derived Astra Project Forge source material.

Astra Project Forge is licensed under **AGPL-3.0**. To the extent permitted by **AGPLv3 Section 7**, covered distributions must preserve reasonable legal notices and author/project attribution associated with Astra Project Forge material.

The goal is proportional credit: the more central the reused Forge material is to a downstream work, the more prominent the attribution should be. Do **not** use artificial percentage thresholds.

## Core attribution notice

Where a downstream work contains Astra Project Forge source material, preserve a clear notice identifying the original project. A suitable baseline is:

> Includes code or portions derived from Astra Project Forge.  
> Original project: https://github.com/Nadzil123/Astra-Project-Forge

Existing copyright and license notices attached to reused Forge material must not be removed or obscured.

## Tier A — Direct Fork

Use when the downstream project is a direct fork or close modified version of Astra Project Forge.

Recommended prominent wording:

> **Derived from Astra Project Forge.**  
> This software is a modified derivative of Astra Project Forge.

Keep the attribution in the README or equivalent primary documentation and preserve `LICENSE`, `NOTICE.md`, and applicable source notices.

## Tier B — Substantial Derivative

Use when Astra Project Forge code forms a substantial or central part of the downstream implementation.

Recommended wording:

> **This project contains substantial portions derived from Astra Project Forge.**

Project-level attribution is appropriate because Forge material is central to the downstream work.

## Tier C — Multiple Components

Use when several Forge components or subsystems are incorporated into a different project.

Recommended wording:

> **This project incorporates components derived from Astra Project Forge.**

Where practical, identify the affected components. Do not imply that the entire downstream project is Forge-derived if that would be inaccurate.

## Tier D — Single Component / Module

Use when one Forge subsystem, module, or file group is reused.

Recommended wording:

> **This project includes a component derived from Astra Project Forge.**

Attribution may appear in README, NOTICE, documentation, or the relevant source area.

## Tier E — Small Code Portion

Use when a smaller but still meaningful portion of Forge code is copied or adapted.

Recommended wording:

> **Contains code derived from Astra Project Forge.**

A local source-header or NOTICE entry is usually more proportional than claiming the whole project is based on Forge.

## Tier F — Tiny / Incidental Portion

For very small copied portions, preserve any applicable notice that accompanies the copied material. A prominent whole-project attribution is not required when it would materially exaggerate Forge's contribution.

Whether a tiny excerpt is copyrightable is a legal question outside this policy; this document does not claim ownership of unprotectable ideas or facts.

## Tier G — Unmodified Redistribution

When redistributing Astra Project Forge essentially unchanged:

- preserve the project identity,
- preserve copyright notices,
- preserve `LICENSE`,
- preserve `NOTICE.md`,
- preserve this attribution information,
- do not present the redistribution as an independently authored original.

## Tier H — Modified Redistribution

When modifying and redistributing Forge:

- preserve original attribution,
- clearly state that the version has been modified,
- preserve the applicable AGPL license and notices.

## Tier I — Commercial Distribution

Commercial use does not remove AGPL or attribution obligations for covered Forge material. Selling, bundling, or monetizing a derivative does not permit removing the origin notices from the Forge-derived portions.

## Tier J — Hosted / Network Use

When AGPL network-source obligations apply to a modified hosted version, comply with AGPLv3 and keep appropriate attribution for Forge-derived material.

## Tier K — Independent Reimplementation

If another developer independently creates software with similar behavior **without copying or deriving Astra Project Forge source material**, the Astra Project Forge source-code license does not automatically apply merely because the functionality is similar.

## Tier L — Ideas / Concepts Only

General ideas, patterns, workflows, and independently implemented architectural concepts are not treated as copied source code merely because they resemble Forge concepts. Attribution is welcome, but this policy does not claim ownership over independently created ideas or functionality.

## No percentage thresholds

Do not use rules such as "20% of the code means substantial." Consider the actual role and importance of the reused material: a small core subsystem can be more significant than a large amount of boilerplate.

## No trademark claim in v2.6

This policy does not establish a trademark program and does not claim that "Astra Project Forge" is a registered trademark.
